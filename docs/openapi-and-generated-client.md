# OpenAPI and generated clients

The authenticated `GET /api/v1/openapi.json` endpoint is the contract source. It is generated by the running binary, so export it from the exact release image or binary used by the client. The specification is OpenAPI 3.1 and includes REST task snapshots plus the `text/event-stream` task event endpoint.

## Export and validate

Initialize a disposable instance, sign in, then export with its session cookie:

```sh
curl --fail --silent --show-error \
  --cookie 'rust_jav_session=<session-value>' \
  http://127.0.0.1:9317/api/v1/openapi.json > openapi.json
npx --yes @redocly/cli lint openapi.json
```

The cookie is a secret: keep the command out of shared shell history and delete the temporary cookie value after export. The checked-in Rust contract test verifies the document version and critical Tasks/SSE, Assets, and detail schemas.

## Generate a TypeScript client

Pin the generator version in consuming projects and regenerate rather than editing output:

```sh
npx --yes @openapitools/openapi-generator-cli version-manager set 7.14.0
npx --yes @openapitools/openapi-generator-cli generate \
  -i openapi.json \
  -g typescript-fetch \
  -o generated/rust-jav
```

Use `credentials: "include"` for same-origin cookie authentication. Treat SSE separately with `EventSource` (same-origin) because generated REST clients generally expose the event response as a string/stream rather than a reconnecting event client. On reconnect, fetch `GET /api/v1/tasks/{task_id}` first; completed and interrupted task snapshots are durable even if events were missed.

## Change workflow

1. Change server request/response types and the OpenAPI document together.
2. Run `cargo test generated_openapi_describes_task_rest_and_sse_contracts` and the full Rust suite.
3. Export from the built release, lint, regenerate into a disposable directory, and review the diff for breaking changes.
4. Run frontend typecheck/tests/build and a task SSE reconnect test.
5. Version intentional breaking changes under a new API prefix; do not silently repurpose `/api/v1` fields.

Generated clients are build artifacts and are not checked into this repository. This avoids stale duplicated contracts; consumers pin the release digest and generated-client tool version in their own lockfiles.
